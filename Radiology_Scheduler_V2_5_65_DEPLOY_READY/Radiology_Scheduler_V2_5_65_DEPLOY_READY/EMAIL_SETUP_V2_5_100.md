# V2.5.100 — email setup

## Goal
One system sender, 16 resident recipients, durable lifecycle notifications:

1. Preferences open.
2. Missing-preference reminders.
3. Swap window open (with preliminary `.ics`).
4. FINAL / done (with final `.ics`).

Every lifecycle event is written to `notification_outbox` before SMTP delivery. The unique `(event_key, initials)` key prevents duplicate delivery after Streamlit reruns or repeated scheduled jobs. A failed email remains retryable instead of disappearing into a transient error box.

## Streamlit Secrets
Use one sender mailbox. For Gmail / Google Workspace, use a Google **App Password**, not the normal account password.

```toml
SCHEDULER_PUBLIC_URL = "https://YOUR-APP.streamlit.app"

[smtp]
provider = "gmail"
host = "smtp.gmail.com"
port = 587
user = "YOUR_SENDER@gmail.com"
password = "YOUR_16_CHARACTER_APP_PASSWORD"
from_email = "YOUR_SENDER@gmail.com"
use_tls = true
use_ssl = false
```

The app's Senior control panel has two checks:
- **CHECK CHANNEL**: connects/authenticates to SMTP without sending mail.
- **SEND TEST TO ME**: sends one real test email to the current operator.

## Background worker
`notification_worker.py` handles automatic preference-stage notices and retries. The bundled GitHub Actions workflow runs twice each morning for EET/EEST safety; event deduplication means only one copy can be delivered.

GitHub repository Actions secrets required:
- `SUPABASE_URL`
- `SUPABASE_SERVICE_ROLE_KEY`
- `SCHEDULER_PUBLIC_URL`
- `SCHEDULER_SMTP_PROVIDER`
- `SCHEDULER_SMTP_HOST`
- `SCHEDULER_SMTP_PORT`
- `SCHEDULER_SMTP_USER`
- `SCHEDULER_SMTP_PASSWORD`
- `SCHEDULER_EMAIL_FROM`
- `SCHEDULER_SMTP_USE_TLS`
- `SCHEDULER_SMTP_USE_SSL`

**Never put the Supabase service-role key in Streamlit client code or in the repository.** It belongs only in the GitHub Actions secret store for the background worker.

## Operational semantics
- `preferences_open`: one email per active resident per target month.
- `preferences_reminder`: only residents whose form is still missing; respects their existing reminder on/off and start-day setting; max one per resident per day.
- `swap_open`: triggered when the operator actually opens the preliminary swap window; attaches the preliminary personal `.ics`.
- `final`: triggered on FINAL confirmation; attaches the final personal `.ics`.
- Failed/blocked lifecycle emails appear in the Senior notification table and can be retried only for failed recipients.

The old separate duplicate `backup_claim_reminder` is no longer generated by the lifecycle reminder path.
